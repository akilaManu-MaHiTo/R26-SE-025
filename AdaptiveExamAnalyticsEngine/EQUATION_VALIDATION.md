# Equation validation

Subsequent update: EQ-01, EQ-02, EQ-03 and EQ-09 were repaired after this baseline audit. Their tests are now ordinary passing regressions. Historical formulas, line references and results below describe the audited baseline; [remediation validation](REMEDIATION_VALIDATION.md) describes the current implementation.

Audit date: 2026-10-15. This is a read-only audit of production equations in the current working tree, including pre-existing changes. No production fixes, model downloads, network model requests, or database writes were performed. Line numbers refer to that tree, not an assumed release. P1 means materially misleading core results, P2 means incorrect results or missing validation under stated conditions, and P3 means a boundary/contract or reporting limitation. Mathematical validity and empirical usefulness are separate verdicts.

Expected failures acknowledge defects; they are not evidence that production is correct. An initial test-only AST loader collection error (missing `lineno`) was fixed before the final run.

The tests call ordinary pure production imports for recommendation scoring, weakness, diagram aggregation and evaluation metrics. For student/exam functions, recommendation signal generation, and cosine similarity, they compile the **unchanged source function bodies** using AST, injecting only dependencies needed to isolate arithmetic from configuration/model/database imports. Student aggregate output classes are lightweight field containers in these checks; schema validation and end-to-end routing are not thereby tested. `--noconftest` avoids the global settings and database fixtures. No `.env` content was read or printed by this test path. Independent expected values are hand-calculated rational values, population-moment identities, and known vector dot products, not a copy of the implementation algorithm.

A percentage is in percent units; a rate is a proportion unless explicitly multiplied by 100. Rounding is presentation-oriented Python `round`, not decimal half-up rounding.

## Empirical justification not established by arithmetic

This audit can establish calculations and counterexamples; it cannot establish that `.35/.20/.15/.15/.15` recommendation weights, composite weakness `.60/.25/.15`, tutorial saturation at three rows, two-year relevance horizon, Bloom target proportions, final-paper `.45/.35/.10/.10`, minimum student/question thresholds, or similarity/priority/status cutoffs improve learning or assessment quality. Repository tuning and rater scripts are potential evidence-generation workflows, not proof of held-out utility. Their NDCG calculation is currently biased (EQ-06). Lecturer-rated usefulness, calibration, temporal holdouts, rater agreement with complete paired labels, and uncertainty by cohort/topic are needed before making predictive or efficacy claims. Do not infer these from passing unit tests or synthetic fixture data.
