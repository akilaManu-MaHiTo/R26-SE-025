# Qwen3-8B Bloom fine-tuning

This folder is a Google Colab-ready Unsloth scaffold for fine-tuning
`unsloth/Qwen3-8B-bnb-4bit` with LoRA. Its assistant output matches the
`QuestionSemantics` contract used by `app/services/llm_service.py`:

```json
{
  "level": "Apply",
  "topic": "Structured Query Language (SQL)",
  "subtopic": "Grouping with GROUP BY and HAVING",
  "confidence": 1.0,
  "reason": "The student applies known SQL operations to a concrete task."
}
```

The bundled `data/example_*.jsonl` files are synthetic smoke-test data. They
are balanced across the six Bloom levels, but they are **not production gold
data**. Replace them with independently lecturer-labelled and adjudicated
questions before evaluating or deploying a model.

## Dataset contract

Each JSONL line is one object with:

- `question_id`: globally unique question-part identifier;
- `group_id`: source exam/tutorial identifier used to prevent split leakage;
- `messages`: exactly one `system`, `user`, and `assistant` message;
- `gold_label`: one of `Remember`, `Understand`, `Apply`, `Analyze`,
  `Evaluate`, or `Create`;
- `annotation_status`: `example_only` or `adjudicated`;
- `annotator_ids`: at least two distinct IDs for an adjudicated record.

Keep all parts from one source document in the same split by assigning them
the same `group_id`. Do not copy a group between train and validation/test.

Validate the supplied examples locally without installing Unsloth:

```bash
python validate_dataset.py data/example_train.jsonl data/example_validation.jsonl
```

For real data, enforce lecturer adjudication:

```bash
python validate_dataset.py --require-adjudicated data/train.jsonl data/validation.jsonl data/test.jsonl
```

## Run in Google Colab

Open `Qwen3_8B_Bloom_Unsloth_Colab.ipynb` for the complete guided workflow,
including GPU checks, Drive persistence, training, export, and inference.

1. Select **Runtime > Change runtime type > T4 GPU**.
2. Clone this repository or upload the `unsloth_training` directory.
3. Run these cells, adjusting the path after `%cd`:

```python
%cd /content/R26-SE-025/V2_QuestionExamPredictionEngine/unsloth_training
!pip install -q -r requirements-colab.txt
```

Smoke-test the pipeline with the included synthetic examples:

```python
!python train_bloom.py --allow-example-data --epochs 1
```

Do not use that smoke-test adapter in production. For real adjudicated data,
create `data/train.jsonl` and `data/validation.jsonl`, then run:

```python
!python train_bloom.py \
    --train data/train.jsonl \
    --validation data/validation.jsonl \
    --epochs 3 \
    --export-gguf
```

Without `--allow-example-data`, the trainer rejects every record that is not
marked `adjudicated`. The LoRA adapter is saved to
`outputs/qwen3-bloom-lora`. `--export-gguf` also creates a `q4_k_m` GGUF under
`outputs/qwen3-bloom-gguf` for Ollama. Colab storage is temporary, so download
the output or copy it to Drive before ending the session.

## Import the GGUF into Ollama

Copy the generated `.gguf` beside `Modelfile.example`, update the `FROM` line
to its exact filename, and run:

```bash
ollama create qwen3-bloom:latest -f Modelfile.example
ollama run qwen3-bloom:latest
```

This is a classification-specialized model. Keep general `qwen3:8b` for
student insights and question generation. The current application has one
global LLM route, so add a separate `BLOOM_MODEL` setting before selecting this
model only in `classify_question_semantics`.

## Before real training

- Use lecturer labels, not labels generated by Qwen.
- Include every Bloom level and inspect the class distribution.
- Keep an untouched `test.jsonl`; never pass it to `train_bloom.py`.
- Compare held-out macro-F1 and per-class recall against base `qwen3:8b`.
- Review adjacent-level errors such as Understand/Apply and Analyze/Evaluate.
- Do not treat the model's `confidence` number as statistically calibrated.
